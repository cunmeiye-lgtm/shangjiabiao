# 素材分配配置与命令

`scripts/allocate.py` 只复制已有素材，不生成、裁切或重新编码图片。先检查 PSD 并建立档案，再把**真实替换组名**写入 `effect_slots[].name` 和 `fixed_slots[].name`。不要从商品编码猜测图案编号。

## 输入配置

```json
{
  "product_key": "商品编码或组合编码目录名",
  "batch_root": "\\\\server\\share\\套图素材\\本批目录",
  "seed": 20261026,
  "pools": {
    "款式A效果图": ["\\\\server\\share\\来源\\已有照片.jpg"]
  },
  "templates": [{
    "name": "模板名称",
    "psd_dir": "\\\\server\\share\\已确认PSD副本\\模板名称",
    "head_slot": "图案2",
    "head_slice": 1,
    "effect_slots": [{"name": "图案2", "pool": "款式A效果图"}],
    "fixed_slots": [{"name": "图案1", "source": "\\\\server\\share\\来源\\完整产品.png"}]
  }]
}
```

- 示例中的 `server/share` 是占位共享路径，须改成当前使用者可访问的实际UNC地址。不要直接执行示例路径。
- `count` 可选，放在每个模板对象中。省略表示使用该模板全部可行且不重复的头图；指定时必须是正整数，超出容量直接报错，不悄悄减少。
- 上例是最小只读规划输入。实际复制还必须在每个模板绑定 `documents` 和 `pages`，缺少时禁止执行。`documents` 恰好4项，分别对应当前 `psd_dir` 下的 `主图.psd`、`详情.psd`、`sku.psd`、`白底.psd`；每项为 `{"path":"完整路径","bytes":文件字节数,"mtime_ns":修改时间纳秒,"sha256":"文件SHA256"}`，必须来自实际检查，不可手填伪造。
- `pages` 使用 `{"verified":true,"main":[1,2,3,4,5],"detail":[1,2,3,4,5],"sku":[1,2]}` 形式，数值来自与这些文档版本对应的实际分页核验。`head_slice` 必须包含在 main 中。脚本在复制前检查所有版本：元数据相同直接复用，元数据变化则核对 SHA；内容变化或不可访问时要求重检，不能沿用旧映射。只读纯元数据回放可以省略这些绑定。
- `seed` 必须由本批输入明确给出；相同配置、像素及种子生成相同分配。
- 一个配置支持一个明确的 `head_slot`。多头图联合去重等新规则必须先扩展配置与算法，不能用此算法冒充已支持。
- `effect_slots` 顺序应按 PSD 实际展示顺序记录，用于跨模板照片集合的排列比较；不按名称字典排序。
- 所有效果位共用“同链接不重复像素”约束，各位可分别指定不同款式池。固定产品、尺寸、显色前后放入 `fixed_slots`，固定页不参与随机位去重。
- 组名保持原样，空格尾缀、路径分隔符及 Windows 保留名直接报错并要求检查档案，不擅自清洗改名。
- 路径必须是绝对路径。脚本允许本机绝对路径用于隔离测试；正式交付路径由上架表构建器强制检查 UNC 可访问性。
- 支持 PNG、JPEG、WEBP、TIFF、BMP 单帧素材，扩展名必须匹配真实格式。库存、价格、SKU、标题由独立表格配置负责。

## 计划与执行

```text
python scripts/allocate.py inventory batch.json
python scripts/allocate.py plan batch.json --output 本批计划.json
python scripts/allocate.py copy 本批计划.json --workers 4
```

`inventory` / `plan` 默认只读取并输出 JSON 到标准输出；只有明确 `--output` 才新建计划文件，已有文件拒绝覆盖。`copy` 是实际执行入口，按清单复制并建立成品目录，不运行精制、不导出图片、不上架。

解码去重使用含尺寸的 EXIF 方向校正 RGBA 像素哈希；复制核验使用原文件 SHA-256。不同文件名或压缩封装的相同解码像素在每个池中只保留一个代表；原文件仍可在 inventory 中追溯。半透明像素保持原有内容，不做颜色容差或近似去重。

每个候选头图用增广路径匹配其余效果位，确保有重叠的多个款式池不会因贪心选图错误减少容量。同一模板只消耗头图，其他位置可以跨链接复用，因此容量不是 `图片数 ÷ 效果位数`。模板按配置顺序循环，某模板完成后其余模板继续循环。

跨模板遇到相同像素集合且排列相同会重试重新匹配，最多 256 次。仍无法避免时明确报错，返回“需调整位置、素材池或数量”，不会输出违反规则的清单，也不会把重试失败说成已证明全局最大容量。逐模板 `capacities` 是不考虑跨模板排列冲突时的精确可行头图数。

## 清单接口与目录

计划根字段：`schema_version=1`、`seed`、`product_key`、`batch_root`、`templates`、`capacities`、`links`、`copies`、`fixed_slots_exempt=true`、`digest`。

`links` 按最终上架顺序，每项包含：

- `id`：从 1 起的连续关联编号。
- `template`、`combination`：模板名称、模板内从 1 起的组合编号。
- `source_folder`：`批次\模板\组合001\商品目录`。
- `output_folder`：`批次\成品\模板\组合001`。
- `psd_folder`：经过验证的模板目录。
- `head_slot`、`head_slice`：去重依据；男5可记第2片，不改变主图输出顺序。

`copies` 每项：`link_id`、`slot`、`role(effect/fixed)`、`source`、`destination`、`sha256`、`pixel_sha256`。目标文件名 = **原样 PSD 替换组名 + 来源真实扩展名**。

`digest` 为除 digest 自身外的整个计划的规范 JSON SHA-256。修改计划后必须重新计划；执行前检查摘要、目录推导、替换位齐全、随机位去重、头图去重。

执行完成后批次根目录包含 `素材分配清单.json`、`素材分配清单.csv`、`素材复制核验.json`。完整清单可恢复来源与替换位；表格生成器直接消费 `links`，不用再从目录排序猜关联关系。

表格制作前调用 `verify_ready(manifest, workers=4)`：复核计划摘要、现有模板版本和分页绑定、落盘分配清单、复制回执中的 `manifest_digest/verified/files`，并重新核对全部目标文件哈希及目录文件名。回执过期、复制后素材被改动、目录多出同名不同扩展名文件等情况均阻止表格制作。返回 `{"manifest_digest":"...","files":数量,"verified":true}`；该函数只读，不修复文件。

复制采用有界线程和流式读写，默认 4 线程，最多 16。每份来源与目标均检查字节哈希；已有匹配文件视为续传，不重新写入；已有不匹配文件或中断留下的残缺文件拒绝覆盖并报出路径。不要自动删除这些文件，先核实是本任务残件，再另存批次或按授权处理。已有不同批次清单也拒绝合并。已有内容但缺少本批清单的批次根目录禁止接管；空目录可新建清单。每个素材目录只允许预期文件名，额外文件、子目录、同组名不同扩展名直接报错保留；已有预期文件的子集允许续传。成品目录只是输出位置，不表示已经生成套图。

## 隔离验收

```text
python -m unittest discover -s tests -p "test_materials.py"
python -m unittest discover -s tests -p "test_allocate.py"
```

测试不生成栅格素材：像素相关测试使用解码 mock，复制和指纹绑定测试使用不解码的字节哨兵；业务回放使用纯元数据。D06 回放 7×140=980 条、6440 文件；四款回放把102张效果图分成4个独立款式池，验证每链接四款基础位及两张指定款式补充效果图、4份产品，17×(6+4)=170 文件。当前通用规则允许其他位置跨链接复用，因此四款回放不宣称 102 张效果图在全批都不重复；历史批次可另行核对实际清单。

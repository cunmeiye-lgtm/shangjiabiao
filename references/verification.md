# 验证、案例与维护

## 可重复检查

使用workspace loader的Python及依赖，测试入口：

```text
python -B -m pytest <skillRoot>/tests -q
```

全套测试使用已有`pytest`；覆盖率可加`--cov=scripts --cov-report=term-missing`，需已有`pytest-cov`。没有这些开发依赖时不自动安装。`unittest discover`只覆盖类式测试，不包含全部多头用例。

`test_allocate.py`纯元数据回放D06七套：140个不同头图/模板、980链接、6440素材；不是重新复制11GB生产目录。四款回放17链接、6效果位+4产品位=170份。`test_business.py`验证1/2/4/6/8款规格数量、两种两张档、固定单张绑定、价格舍入和17SPU/85SKU。`test_multihead.py`覆盖联合头图、23图四模板容量、完整池绑定、位置排列及执行门禁；实际复制仍需真实解码验证，纯元数据测试不能替代。

素材测试覆盖相同像素不同文件、池重叠的完整匹配、素材不足、跨模板排列冲突、固定页豁免、错误替换位、路径越界、PSD变化、续传及已有冲突文件；使用解码mock或现有文件，不用脚本生成测试图片。

模板缓存测试区分元数据匹配、严格SHA匹配、变化和不可访问。表格测试覆盖表头错位、预期值变化、Artifact回读不一致、样式/公式变化、原生批注/分页对象限制、只改字段、文件占用另存、源文件并发变化及已有输出保护。

`test_listing_state.py`用最小OOXML文本固件检查同店历史、不同店铺、NFKC、真实链接编号、同批沿用/旧标题占用、并发锁、版本漂移和原子提交；不使用openpyxl作者接口。`test_business_upgrade.py`检查中文逗号、可配置营销名不改变发货数据，以及真实关联编号传入历史门禁。`tests/cases`保留真实CLI可拒绝的非法种子和未知状态schema反例。

## 真实表格集成

可选环境变量：`JINGZHI_INTEGRATION_SOURCE`指定只读精制基底，`JINGZHI_NODE`为bundled Node，`JINGZHI_INTEGRATION_WORKDIR`为专用暂存根目录（含指向bundled node_modules的junction）。开启后测试运行实际Artifact新建与修改，再读回并渲染。不开启则该集成测试明确显示skip，不能宣称实际引擎测试通过。

本技能不是单独的无模型批处理程序：AI负责理解产品、选择基底与确认配置、检查新PSD、撰写自然标题和审阅图像/表格预览；脚本负责确定性计算、复制、写表和自动核验。测试覆盖不能证明所有商品文案正确，不能证明精制已经导入或发布。

## 案例与版本

- D06：历史批次980SPU/4900SKU，7模板循环，随机位4340份、产品980份、显色前后各560份。固定显色后与池中一张照片相同，用户已明确固定页豁免。价格曾使用1.5倍G档，不作未来默认。
- 四款福字：历史17SPU/85SKU，编码A2004/A2064/A2065/A2066。单张显示名“随机一张”绑定A2004；两张档分别为前两款/后两款；SKU图位置当时为1/2/3/1/1。换模板后必须重新映射。
- 最新通用规则替代旧的“同模板全批效果图只能用一次”；只有头图跨本模板链接不重复。历史四款批次曾有全批102效果图不重复，这是当时的更严格批次条件，不能默认为本算法承诺。

案例文件只作为只读证据。技能升级在隔离目录验证，保留用户已有目录与打开文档。新增业务规则先补失败用例再修改对应模块；对SKU/路径/表格保真进行独立审查，执行skill-creator的quick_validate校验名称、frontmatter、未完成占位及文档引用。不要把测试通过等同于生产上架完成。

# 纹身与皮肤真实融合

把已经放在皮肤上的纹身图案处理得像自然贴合皮肤的平面墨色。保留产品款式和原照片，以皮肤纹理、光照及身体曲面的融合为编辑目标。

## 范围与工具

- 从当前请求和本批已确认信息取得输入、输出、命名与特殊效果要求。目录明确且已要求执行时直接开始，不重复要批准。缺少输入或输出位置会阻断保存时才集中询问。
- **实际图像编辑必须使用AI。** 默认调用当前可用的内置 `image_gen` 图片编辑工具；如有 `imagegen` 技能，遵循其工具与保存规范。不能用 Python、Pillow、OpenCV、Photoshop脚本、透明度叠加、调色或程序合成替代AI编辑。
- 文件枚举、读取尺寸、哈希、原样复制与写处理记录可以用文件工具或脚本；这些操作不能重新编码或修改图片像素。只用AI生成服务返回的真实输出文件作成品。
- 图片会作为参考输入交给AI服务，成品和处理记录写入用户授权的位置。不要额外上传网盘、发送给他人、发布商品或推送业务素材到仓库。
- 内置工具不可用时报告阻断；只有用户明确选择CLI/API备用方式后才使用受支持的备用流程。需要密钥时让用户在本机配置，不索取聊天中的完整密钥，不静默安装工具或改全局配置。

## 清点与命名

1. 确认实际输入目录可读、目标目录可写，解析实际路径，目标不能与输入目录相同，任何成品路径不能指向源文件。先记录源文件相对路径、SHA-256和实际尺寸。默认纳入目录及子目录中的照片；排除本批输出目录、已明确识别的历史成品/缓存，以及符号链接或目录联接，避免重复处理与越界。记录纳入、排除和不可读取项。未明确排除的普通图片不能因名称像成品就静默略过。
2. 按实际格式识别PNG、JPEG、WebP等可读取照片；不把PSD、图案源稿或非照片文件直接送去融合。工具不支持的格式单列，不能假装完成。所有本地编辑目标先通过 `view_image` 或当前支持的图片查看工具逐张加载，检查图案、部位、遮挡和是否有其他原有纹身。
3. 默认保留原文件名，成品**全部平铺**到指定目录；用户要求从01开始时，按固定自然顺序预先分配 `01、02……`，失败项保留编号，不把后续文件前移。未指定名称时不要自行重编号。不同子目录重名，用相对目录前缀消歧，按目标文件系统大小写规则检查冲突，并写入映射。
4. 名称扩展名与AI输出真实格式一致：PNG沿用 `.png`；JPEG输入而工具返回PNG时用同名 `.png`，不能只改后缀冒充JPEG。确定真实输出扩展名后再次检查整批冲突，例如同目录 `01.jpg` 与 `01.png` 都返回PNG时，将源扩展名纳入消歧名称（如 `01-jpg.png`、`01-png.png`）并更新映射。不为恢复原尺寸用代码缩放；记录实际成品尺寸，用户有严格像素要求时采用工具支持的尺寸能力，无法满足则说明。
5. 不覆盖原图、已有文件或删除历史成品。目标存在时，只有处理记录中的源图哈希、编辑提示词/模式、输出哈希均匹配且先前视觉检查有记录，才可复核实际文件并续用；证据缺失、源图变化或目标不一致时另存有意义的版本名并报告。明确授权覆盖时才覆盖对应目标，仍保护源图。

## 逐张AI编辑

读取[提示词](references/prompts.md)，按目标是黑色、彩色或明确指定的刚揭下状态选择。将当前照片标记为**编辑目标**，每次只编辑一张；不要把整个批次或拼图当成一个生成目标。

- 保留图案的笔画、符号、八卦结构、花瓣、蝴蝶翅脉和细线等产品特征，不重画款式、不增删元素、不镜像，不改变大小、位置、方向或覆盖范围。
- 墨色顺应局部光照、肤色和曲面；保留毛孔、皮纹、细小褶皱、原有汗毛及适度透肤感。边缘只做必要的自然过渡，不能靠整图模糊、重度变淡或磨皮制造融合。
- 黑色保持自然深炭黑与清晰度；彩色保留原色系、层次和水彩留白。避免统一数值透明度；不同光照、肤色和部位逐图判断。
- 纹身保持平面，无凸起、投影、塑料膜或额外亮边，不添加红肿。衣服、首饰、人物姿态、身体轮廓、静脉、背景、光线和构图尽量保持原样。AI编辑不能保证非目标区域逐像素不变，不作这种承诺。
- 同一照片有另一处原有纹身时，明确指出本款的部位和图案，只编辑本款，保护其他纹身。不要把“已有黑色纹身”泛化为照片中的所有纹身。
- 分小批推进，按工具容量使用有限并发（例如2～5张），不一次提交全部图片。每张结果与其输入绑定，分批查看并记录状态，不能依赖响应到达顺序命名。

默认是**正常显色的真实融合**。以前对其他图片提出的“近乎透明”“去掉灰蓝痕迹”不自动成为新批次默认。只有当前任务明确要求刚揭下、透明或显色阶段时才切换；去除纹身是另一个任务，不能借融合名义擦掉图案。

## 检查、保存与失败处理

按[验收与处理记录](references/verification.md)逐张比较原图与AI结果，特别检查细节缺失、错字/错卦、形状漂移、额外纹身、手部畸变和画面变化。视觉检查用真实图片，哈希或尺寸不能证明图案正确。

质量偏差明确时，从原图重新编辑并只收紧对应约束；每张最多两次质量修正，仍不合格则标记失败，保留候选及原因，不交作成品。服务超时等技术故障最多重试两次，避免无限提交。

安全系统拦截时记录受阻文件和返回原因，不改写敏感描述、裁切或换工具来规避拦截。其余图片继续完成；缺失项单独报告，不用原图、别张图片或失败候选补数。正常照片也可能被工具拦截，分类是工具结果，不据此给用户素材定性。

视觉合格后，从服务返回的实际生成路径原样复制到对应成品路径。保留生成源文件；不猜生成文件名或写入工具不支持的输出路径参数。复制后回读文件并核对SHA-256。工具返回正在运行的会话时，使用匹配的等待/轮询接口取得终态，再判定是否成功；没有退出码不等于失败。

输出目录只放成品图，不分子文件夹、不打包。处理记录放在该目录旁或任务记录目录，不把日志、清单、预览拼图和失败候选混入成品目录。收尾核对纳入数量、完成/失败数量、名称映射、可读取性、尺寸、复制哈希及原图哈希。

## 交付

简短说明实际完成数、保存目录、命名方式、原图是否保留，给出可点击路径；提供处理记录及实际提示词/模式。全部纳入项均通过文件检查和逐张视觉检查后才说全部完成。部分失败时写明成功数和具体缺失项，不能只写“已完成”。

这是需要AI图片能力的执行指引，不是独立生图程序；静态skill检查不等于新批次已完成，更不等于视觉效果或多轮遵循稳定性已经验证。

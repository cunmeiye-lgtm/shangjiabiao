# 验收与处理记录

## 验收属性

文件属性可用只读文件检查；视觉属性必须查看最终真实图像并与原图比较。清单中的自报状态、相同哈希、尺寸和文件数量均不能替代视觉比较。

| ID | 属性 | 检查与证据 | 失败后的动作 |
|---|---|---|---|
| V1 | 产品图案完整 | 原图与成品逐张比较笔画、符号、细线、颜色；八卦逐组对照，不从猜测文字重画 | 从原图定点修正；仍错则不合格 |
| V2 | 纹身与皮肤融合 | 最终图片中墨色顺光、纹理自然，无膜边、凸起、投影；不能单靠变淡 | 只修正具体贴图感或模糊问题 |
| V3 | 非目标画面保持 | 逐张比较人物姿态、身体轮廓、手指、衣物、首饰、其他纹身和背景 | 明显漂移重新从原图编辑；不承诺逐像素一致 |
| F1 | 不漏项、不串图 | 固定输入/输出映射，纳入数=完成数+失败数；按文件核对绑定的AI输出 | 缺项/错配阻断全部完成声明 |
| F2 | 原件与已有文件安全 | 编辑前后源图SHA-256一致；目标冲突有版本名或明确覆盖授权 | 停止覆盖，保留双方文件 |
| F3 | 成品保存完整 | 回读实际格式及尺寸；成品SHA-256=对应生成源文件SHA-256 | 修复复制；无法回读不交付 |
| F4 | 平铺与真实格式 | 指定目录只含合格成品，无子目录/压缩包；名称无大小写冲突，后缀符合真实格式 | 修正名称/位置，不伪造格式或尺寸 |

V1～V3在交付阶段逐张检查；可先用全图检查构图，再在可用查看工具支持时放大纹身细节。没有查看条件就记录未验证，不能凭图片生成服务的文字说明写“视觉合格”。F1～F4在最终保存路径核对；之前的候选检查不能替代成品回读。

## 记录内容

在成品目录之外保存一份JSON或等价记录，至少包括：

- 实际AI工具/模式，原图根目录和成品目录，本批编辑要求及实际提示词（或提示词ID与完整文本）。
- 每张输入相对路径、源图SHA-256、原尺寸；固定输出文件名、实际生成源路径、输出SHA-256及成品尺寸/格式。
- 逐张的视觉检查结果、具体问题与修正次数；文件检查结果；工具失败、拦截和缺失项。
- 完成数、失败数和排除项及原因；时间信息使用当前用户时区。

只在任务本地记录真实业务路径，不将照片、生成结果、用户目录、密钥或批次记录放进skill安装目录或提交到代码仓库。

## 恢复与结论

- 断点续做重新计算当前输入和输出哈希，核对提示词/模式与记录。仅同名文件不证明已处理；旧记录变化或缺失则保留现有文件，另存新版。
- 复制通过但视觉失败：保留为候选，不能算完成；输出文件数不等于合格数。
- 成品检查通过但输入文件被他人改动：记录版本不一致，不能把旧结果当作新版输入的完成结果。
- 视觉明显有误但哈希/数量全部通过，是文件检查可能逃逸的反例，必须由V1～V3拦住。
- 正常例：黑色和彩色各一张，纹理自然且图案完整，最终保存与生成源哈希一致。
- 失败例：输出缺一张、PNG被命名为JPEG、重复基名覆盖、漏掉书法一笔，任一情况都不能声称全部完成。

每批重新检查实际产物。该记录支持追溯，不是给skill自身签发长期稳定或自动视觉正确的证明。

# 精制素材分配与上架表

供团队内部使用的 Codex 技能，技能名称 `jingzhi-listing`。

根据 PSD 的实际替换位计算链接数量、复制分配已有图片，并制作精制拼多多上架表。支持单款及 2、4、6、8 款组合，也支持只修改已有表的指定字段。生成的素材和工作簿供精制工具后续使用；技能本身不发布商品。

## 安装到同事的电脑

当前验证环境为 Windows + Codex 桌面应用。先下载仓库 ZIP 并解压，将包含 `SKILL.md` 的整个文件夹命名为 `jingzhi-listing`，放到：

```text
%USERPROFILE%\.codex\skills\jingzhi-listing
```

若已自定义 `CODEX_HOME`，则放到该目录的 `skills\jingzhi-listing`。最终必须直接存在 `jingzhi-listing\SKILL.md`，不要多套一层仓库文件夹。安装后重新打开 Codex 并新建对话，用 `$jingzhi-listing` 调用。

更新时先备份现有技能目录，再用新版本完整替换；不把业务配置或素材保存在安装目录。仅更新这个技能，不覆盖整个 `.codex` 目录。

## 运行条件

- Codex 能访问本机文件及业务共享盘；上架表中的素材、PSD、成品路径使用当前账号可访问的 UNC 路径。
- 制表需当前可用的 `spreadsheets:Spreadsheets` 技能、`load_workspace_dependencies` 工具及其提供的 Artifact Tool、Node 和 Python 依赖。技能不是独立运行的软件，也不附带这些运行时。
- Python 脚本使用 Pillow、openpyxl（只读）和 lxml。优先使用 Codex 提供的依赖，不向同事电脑静默安装软件或修改运行时。
- 新 PSD 的结构和分页须有实际检查证据；需要原生导出验证时还需可用的 Photoshop 环境。已有档案仅在文件版本匹配时复用。

若同事的 Codex 没有上述表格能力，可以先计算和分配素材；完整制表需先补齐受支持的运行环境，不能把未验证的输出当作完成品。其他客户端尚未验证。

## 怎么使用

在 Codex 对话中输入，例如：

```text
$jingzhi-listing
请先检查我提供的模板档案和素材，计算可做多少条链接。
素材目录：填写实际目录
模板目录或档案：填写实际路径
```

整批制作时再提供：

- 商品编码及款式顺序、固定单张款、尺寸档、SKU 名称和图片位置的特殊要求。
- 本批店铺 UID、价格表及工作表名称、保存草稿值。
- 精制上架表基底、素材批次目录、成品目录和上架表输出路径。
- 要做的链接数量，或明确要求按可行容量制作；已有信息无需重复提供。

“1.5倍”表示读取价格表同名工作表，不是把旧售价乘以 1.5。保存草稿、上架模式和上架状态是不同字段。

同一链接的随机效果位不重复，同一模板的头图不重复；其他位置跨链接可复用。固定产品、尺寸和显色对比图可复用。多模板按轮循环排列，图片名称来自实际 PSD 替换组名。

交付包括上架表、素材分配清单和核验记录。“素材准备完成”不代表已经套图或已经发布商品。

## 团队数据与仓库

仓库根目录直接放本文件、`SKILL.md`、`agents/`、`references/`、`scripts/` 和 `tests/`。建议使用私有仓库，由负责人管理成员访问。

PSD、产品图、效果图、价格表、上架表基底、真实模板档案和批次配置由团队在业务共享盘维护，均不包含在技能包中。历史 D06 和四款案例仅用于回归验证；它们的店铺、数量和价格不是新批次默认设置。

不要把整个业务项目上传。`.gitignore` 用于防止常见素材、表格和临时文件误入仓库，但上传前仍应核对文件列表，避免提交个人路径、账号资料及真实批次清单。

## 维护与测试

业务规则入口为 [SKILL.md](SKILL.md)，脚本接口及模板档案格式在 `references/`。在仓库根目录使用带上述依赖的 Python 运行：

```text
python -m unittest discover -s tests -p "test_*.py"
```

真实 Artifact 集成测试的准备方式见 [验证说明](references/verification.md)。未配置集成环境时对应测试会跳过；不能据此宣称制表引擎已通过验证。首次在同事电脑使用时，先用少量真实素材在隔离目录完成一轮分配、制表和精制预览核验。
